# Rewriting mruby in Rust: analysis and roadmap

This document covers what mruby is made of, how each part maps to Rust, what
ruruby already implements, and the order in which to build the rest.

**Goal (decided after step 2):** ruruby is a new language with Ruby-based
syntax, not a Ruby port. mruby is the structural reference, not a
compatibility target: Ruby features and quirks are added only when the
language wants them, and the syntax will change. mruby's test suite remains a
useful health signal, not a score to maximise.
The mruby checkout analysed lives in `./mruby` (git-ignored; commit `7ecfbf6`, Oct 2026).

## 1. What mruby is

mruby is an embeddable Ruby 3.x implementation. Its design priority is
**memory > performance > readability** (`doc/internal/architecture.md`).

```text
Ruby source ──Prism──▶ AST ──codegen.c──▶ irep (register bytecode) ──vm.c──▶ result
                                              │
                                              └──dump.c──▶ .mrb file ──load.c──▶ irep
```

Size of the C code:

| Part | Lines | Where |
|---|---|---|
| Core runtime | ~40k C | `src/*.c` |
| Standard library + tools (gems) | ~85k C | `mrbgems/*/src` (excluding Prism) |
| Core library written in Ruby | ~9k Ruby | `mrblib/`, `mrbgems/*/mrblib` |
| Test suite | ~17k Ruby | `test/t/*.rb`, plus per-gem `test/` |
| Parser | Prism (vendored submodule) | `mrbgems/mruby-compiler/lib/prism` |

The biggest single files are `class.c` (5.3k lines), `vm.c` (5.2k),
`string.c` (4.7k), `numeric.c`, `array.c`, `hash.c`, `gc.c` (2.5–2.8k each),
and `mruby-compiler/src/codegen.c` (7.4k).

### Key subsystems

| Subsystem | mruby files | What it does |
|---|---|---|
| Values | `include/mruby/value.h`, `boxing_*.h` | `mrb_value` is one word: NaN-boxing / word-boxing / no-boxing. 31 type tags (`MRB_TT_*`). |
| Objects | `object.h`, `class.h`, `string.h`, `array.h`, `hash.h`, `proc.h` | Every heap object starts with `RBasic` (class ptr, type tag, GC color, flags). Max 5 words per object. |
| GC | `src/gc.c` | Tri-color incremental mark & sweep, optional generational mode, write barriers, "GC arena" for protecting temporaries in C code. |
| Symbols | `src/symbol.c`, `presym` | Interned identifiers. Many are pre-interned at build time ("presym"). |
| Classes | `src/class.c`, `variable.c` | Method tables, singleton classes (`SCLASS`), include via `ICLASS` proxies, ivars/cvars/constants, method cache. |
| Compiler | `mruby-compiler/src/codegen.c` | Walks the Prism tree, allocates registers, emits ~120 opcodes into `irep`s. |
| Bytecode | `include/mruby/ops.h`, `irep.h` | Register machine: `R0`=self, args/locals, then temps. Variable-length operands (`B`, `BB`, `BS`, `W`, `EXT1-3`). Each irep has a literal pool, symbol table, child ireps and a catch-handler table. |
| VM | `src/vm.c` | One `mrb_vm_exec` loop; explicit call-info stack (`mrb_callinfo`), value stack, `REnv` for captured locals, `setjmp/longjmp` unwinding. |
| Fibers | `mruby-fiber` | Each fiber is an `mrb_context` with its own stacks, switched by the VM loop. |
| Serialization | `dump.c`, `load.c` | `.mrb` binary format (used by `mrbc`). |
| Embedding API | `include/mruby.h` | `mrb_open`, `mrb_define_method`, `mrb_get_args`, `mrb_funcall`, `mrb_load_string`, `RData` for wrapping native structs. |
| Build system | `Rakefile`, `build_config/`, `*.gembox` | Ruby/Rake picks gems, cross-compiles, and generates `gem_init.c` and presym tables. |

## 2. How each part maps to Rust

| mruby | Rust approach | ruruby status |
|---|---|---|
| `mrb_value` + boxing | NaN-boxing: `struct Value(u64)`, read through its view `heap.kind(v)` (`enum V`). Floats are their own bits; nil/booleans, 48-bit Integers, Symbols and heap handles (type · 13-bit generation · index) use the NaN space. Larger Integers are boxed in the heap and still read as `V::Int`. No `unsafe`. | done (step 6), `src/value.rs` |
| `RBasic` heap objects + GC | One arena per object type; a `Value` holds a `Copy` handle (slot index + generation) read through the heap (`vm.heap[h]`), so no `unsafe`, and a stale handle panics. Stop-the-world mark-sweep at safe points of the main loop, so natives never need mruby's "GC arena". Later: incremental marking, classes in the heap. | done (step 4); classes still `Rc` |
| `mrb_state` | `struct Vm` owning the symbol table, class registry and globals. No global state, so many VMs can coexist (like mruby). | done |
| `symbol.c` | `SymbolTable` with `HashMap<Rc<str>, Sym>`. Presym becomes a `const` table generated by `build.rs` or a macro. | done (runtime-interned common syms) |
| Method tables, `ICLASS`, `SCLASS` | `RClass { methods, includes, smethods }`. Next: real singleton classes, a global method cache keyed by `(class_id, sym)`, `prepend`, refinements. | basic |
| Prism parser | A hand-written, pure-Rust lexer and parser. ruruby must build for wasm, which rules out the `ruby-prism` crate (C bindings). | near-complete Ruby syntax (`lexer.rs`, `parser/`) |
| `codegen.c` | Same algorithm: scope stack, register stack pointer, jump patching, catch tables. | done for the supported syntax (`codegen.rs`) |
| `ops.h` / `irep` | `enum Op` with typed operands. Add an encoder/decoder to mruby's byte format for `.mrb` compatibility and denser code. | enum form (`opcode.rs`) |
| `vm.c` dispatch | `match` in one loop over an explicit frame stack (`Vec<Frame>`, mruby's callinfo stack). Natives calling back into Ruby nest the loop, as C functions do in mruby. Later: a flat value stack instead of a heap `Env` per frame. | done (step 3); registers still in per-frame `Env`s |
| `setjmp/longjmp` | `Result<T, Unwind>` + `?`; `Unwind::{Error, Break, Return}`. Catch tables are consulted per frame, as in mruby. | done |
| `REnv` | `Rc<Env>` with `upper` chain; `GETUPVAR/SETUPVAR(idx, depth)`. | done (every frame's registers live in an Env; mruby only heap-allocates on capture) |
| C functions (`mrb_func_t`) | `fn(&mut Vm, &Value, &[Value], Option<&Value>) -> VmResult`. `mrb_get_args` becomes small typed helpers (`int_of`, `str_of`, …) or a derive macro later. | done |
| `mrblib/*.rb` | Mostly ported to Rust; the iterators (`each`, `map`, `times`, `loop`, …) are Ruby in `core/prelude.rb`, compiled into every VM, so their loops reach GC safe points and need no native stack. | Rust + `prelude.rb` |
| `RData` | `Value::Data(Rc<dyn Any>)` + a `DataType` trait (`fn free`, `fn mark`). | todo |
| mrbgems | Cargo features/crates: `ruruby-io`, `ruruby-time`, … each with `fn init(vm: &mut Vm)`. A `gembox` = a feature set. | todo |
| `mrbc`, `mruby`, `mirb` | binaries in `src/bin/`; `--dump` already mirrors `mruby -v`. | `ruruby` binary (script, `-e`, stdin, REPL, `--dump`) |
| `test/t/*.rb` (`mrbtest`) | Port `test/assert.rb` and run mruby's own `.rb` tests through ruruby. This is the best conformance metric. | 13 Rust integration tests |

### Rust-specific pitfalls

* **Never hold a `RefCell` borrow across a call into the VM.** A block can
  mutate the array you are iterating. Copy what you need, release the borrow,
  then call. All of `core/` follows this rule.
* **Heap handles need the heap.** Read objects with `vm.heap[h]`. Don't hold
  that borrow across anything that allocates or calls into the VM, including
  temporaries: in `vm.str(vm.heap[s].borrow().clone())` the `Ref` lives until
  the end of the statement. Bind the copy to a `let` first.
* **Safe points.** Collection only happens between instructions of the outermost
  loop of `run_main`, so native code can hold `Value`s in locals freely. A host
  that keeps a `Value` across a later `eval` must keep it reachable from the VM
  (a global, a constant). `--gc-stress` (CLI, mrbtest) collects at every safe
  point, which turns a missing root into an immediate "use of a freed object" panic.
* **Classes are `Rc`.** A cycle through an anonymous class's own singleton
  class or constants leaks; named classes live forever anyway.
* **Native recursion depth.** Ruby→Ruby calls run on the VM's own frame stack
  (capped at 10 000 frames), so they need no native stack. Natives calling back
  into Ruby (`each` with a block) do recurse: about 3 KiB per level in release,
  24 KiB in debug. That recursion is bounded by measured stack use against
  `Vm::stack_budget` (512 KiB on wasm, 1 MiB elsewhere; the CLI raises it), so
  it raises `SystemStackError` instead of crashing. The parser and codegen
  recurse per nesting level, which `parser::MAX_DEPTH` bounds; keep parser
  frames small (box large `Node` variants, `#[inline(never)]` on cold helpers)
  so the limit can be raised toward Prism's 256.
* `sort_by` in std may panic on inconsistent comparators, and Ruby `<=>` can be
  anything, so `core::merge_sort` is a small stable sort that propagates Ruby exceptions.

## 3. What ruruby implements today

Pipeline: lexer → parser (locals resolved per scope, like Prism) → AST →
register codegen → `Irep` → VM.

Language (after step 2):

* **Literals:** numbers (`0b`/`0o`/`0x`/`0_10`, `1_000`, floats), strings with
  escapes (`\x`, octal, `\u{…}` bytes combined into UTF-8) and interpolation
  (including `"#@ivar"`), adjacent-literal concatenation, `?c`, heredocs (`<<ID`,
  `<<-ID`, `<<~ID`, quoted), `%w %W %i %I %q %Q %s %r`, symbols (`:"a#{b}"`), arrays
  and hashes with splats (`[*a]`, `{**h, x:}`), ranges (beginless and endless),
  regexp literals (compiled to `Regexp.compile`, as in mruby), `__FILE__`,
  `__LINE__`, `__ENCODING__`, `__method__`.
* **Variables:** local, instance, global, class variables (`@@x`), constants
  (`A::B`, `::C`, `A::B = v`), multiple assignment with nesting, splats and
  attribute/index targets (`a, (b, *c), o.x, h[:k] = …`), op-assign on any target
  (`a ||= v` is `a || a = v`, as in Ruby).
* **Methods:** full parameter lists (`a, b = 1, *rest, c, k:, k2: 2, **kw, &blk`,
  `(a, b)` destructuring, `...` forwarding, anonymous `*`/`**`/`&`), endless
  `def m = expr`, `def obj.m`, `def self.m`, operator and setter names,
  keyword arguments with missing/unknown checks, `alias`, `undef`.
* **Blocks:** the same parameter lists (with proc auto-splat, `|a, |`, block-locals
  `|a; b|`), numbered parameters `_1`…`_9` and `it`, lambdas `->(x) {}` with strict
  arity and their own `return`/`break`, `&blk`, `&:sym`.
* **Control flow:** `if/unless/while/until/case/for` (and modifiers),
  `begin … end while`, `break/next/redo/retry/return` (also leaving `ensure`
  regions, which then run), `begin/rescue/else/ensure`, `rescue *list`,
  `rescue => @var`, safe navigation `&.`, `defined?`, `BEGIN/END { }`.
* **Pattern matching:** `case/in`, `expr => pat`, `expr in pat`, with value,
  binding, alternative (`|`), capture (`=> x`), pin (`^x`), array, find
  (`[*, x, *]`), hash (`{k:, **rest}`, `**nil`) and `Const(...)` patterns, and
  guards. Patterns are desugared in the parser into `===`/`deconstruct` calls.
* **Classes:** real singleton classes (`class << obj`, `extend`,
  `singleton_class`), `prepend`, `Class.new`/`Module.new` (named when assigned
  to a constant), `define_method`, `instance_eval`/`class_eval`, `method_missing`,
  include/extend/inherited hooks.

Core library: Kernel (`puts p print format raise loop Integer() Float() send
respond_to? is_a? tap then dup instance_variable_get/set …`), Module/Class
(`new attr_accessor include ancestors instance_methods === …`), Comparable,
Enumerable (≈45 methods, also for user classes that define `each`), Integer,
Float, Math, String (≈60 methods), Symbol, Array (≈60 methods), Hash (≈40
methods, default values), Range, Proc, NilClass/TrueClass/FalseClass, the
standard exception hierarchy.

Tooling: `ruruby file.rb`, `ruruby -e '…'`, stdin, a REPL (`mirb`-style),
`--dump` bytecode disassembly.

Verified: `examples/*.rb` produce the same output as CRuby, apart from error-message
wording (ruruby uses Ruby 3.4's wording) and `2**-1` (Ruby returns a Rational).
`cargo test` runs 32 end-to-end tests (`tests/language.rs`, `tests/syntax.rs`,
`tests/call_stack.rs`, `tests/gc.rs`), the harness test, and `tests/parse_corpus.rs` (compiles every `.rb` file in
`./mruby`).

Known limitations of Hash (see the roadmap for the rest):

* `Hash#==`/`#eql?` and equality of nested containers compare keys with the
  built-in `eql?`, so objects that define their own `hash`/`eql?` compare by
  identity there (lookups do use their methods).
* Creating many tiny hashes is ~25% slower than CRuby 2.6.
* A small hash is scanned up to 8 pairs (mruby: 16), and an indexed hash asks
  `eql?` only of keys with the same hash (like CRuby), so mruby's tests of
  `eql?` callbacks that modify the hash differ in those shapes.

Object model (step 5): method visibility (private/protected/public with
names or as a scope's default, module_function, enforced on calls,
introspection by visibility, shared with blocks), subclasses of Array, Hash
and String (and instance variables and singleton methods on their values),
frozen objects (FrozenError from every change), Method and UnboundMethod
objects.

## 4. Roadmap (suggested order)

Each step can be checked against mruby's own tests.

1. **Run mruby's test suite.** ✅ Done, see section 6. Baseline: 247 of 923
   assertions pass (26.8%).
2. **Parser completeness.** ✅ Done with the hand-written parser (pure Rust, for wasm).
   Syntax now blocks 1 assertion instead of 309; 593 of 970 pass (61.1%). Still
   missing: a heredoc *started inside* `#{…}` whose body follows on the outer
   lines (needs interpolations lexed inline instead of as raw text), and a real
   `Regexp` class (literals already compile to `Regexp.compile`).
   **2b.** ✅ Gaps found by compiling every `.rb` file in the mruby checkout
   (`ruruby -c`, now the `parse_corpus` test): 279 → 290 of 297 files compile;
   the rest are Rational/Complex/Bignum literals (step 7) and heredocs started
   inside `#{}` (not supported, a Ruby oddity). Also: `#{}` is lexed by the main
   tokenizer; binary operators use precedence climbing (one table, `binary_op`);
   nesting is limited to `parser::MAX_DEPTH` = 100 levels, so deep input is a
   SyntaxError instead of a stack overflow (a release build needs ≤ ~740 KiB of
   stack at the limit, within wasm's default 1 MiB).
3. **Explicit call stack.** ✅ Done. One dispatch loop (`Vm::run_frames`) runs
   Ruby→Ruby calls (methods, `yield`/`Proc#call`, `super`, `method_missing`,
   `define_method`, class bodies, user-defined operators) on `Vm::frames`
   without native recursion; unwinding (rescue, `break`, block `return`,
   `ensure`) walks the frames. On a 1 MiB stack method recursion went from 536
   levels to the 10 000-frame cap; speed is unchanged. Still natively
   recursive: natives that call blocks (`each`, `map`, …). Moving the common
   iterators to Ruby, as mruby's `mrblib` does, would make those in-loop too,
   and Fibers can only switch between frames of one loop. The single value
   stack is left for step 6.
4. **Garbage collector.** ✅ Done: typed arenas with generation-checked
   handles, stop-the-world mark-sweep at safe points, `GC.start/count/enable/
   disable/stress/live`, and iterators moved to Ruby (`prelude.rb`) so their
   loops collect. Cyclic garbage that used to leak (76–158 MB for 300k
   iterations) now stays at about 5 MB. `fib(30)` got faster (0.95 → 0.79 s);
   iterator-heavy code is slower (`each` 0.19 → 0.43 s) until step 6. Later:
   incremental marking with write barriers, classes in the heap, `ObjectSpace`.
5. **Object model fidelity.** Singleton classes, `extend`, `prepend`, class
   variables, `define_method`, `instance_eval`/`class_eval`, `method_missing` and
   lambdas arrived with step 2. Still missing: visibility (private/protected),
   `respond_to_missing?`, `Method`/`UnboundMethod`, frozen objects, and subclasses
   of built-in classes (`class X < Array` instances are plain objects, which is what
   most of `hash.rb` trips over).
6. **Performance.** 🚧 In progress. Done: one value stack for all frames'
   registers with envs only for captured locals (as mruby), simple calls bound
   straight from the caller's registers, results computed in their destination
   register, `ADDI`/`SUBI`, `i += n` as one instruction, discarded statement
   values not copied, `step` inlined into the dispatch loop, inline method
   caches on `Send`, and classes in the GC heap so `Value` is `Copy`.
   `fib(30)` 0.79 → 0.23 s, a counting `while` loop 2.80 → 0.65 s (30M
   iterations; CRuby 2.6: 0.69 s), `times`/`each` 3.3× faster (later
   0.18 s / 0.48 s, see below). CRuby 2.6 runs
   `fib(30)` in 0.14 s. Tried without gain (reverted): 16/24-byte instructions,
   compare-with-immediate instructions, splitting rare instructions out of the
   dispatch loop — each changed the large dispatch function's code for the
   worse. An instruction-level profile (`tools/pcprof.py`, lldb-based) and the
   loop's disassembly then showed the collector and the exception handler
   inlined into the dispatch loop; moving them out made the loop 17% faster
   (0.54 s now, beating CRuby 2.6). The profile also shows the loop keeping
   `self`, the frame and `pc` on the stack (one ~37 KB function, too many live
   values for the registers) and ~13% of a call spent copying 208-byte frames
   (boxing them was worse: one more indirection per field access). Then the
   dispatch loop was cut down to the simplest instructions and Integer fast
   paths, with `Send` and everything else out of line (`send_op`,
   `step_slow`, which fetches its own instruction so the loop never copies an
   `Op`), and the method epoch became an atomic (a thread-local read is a
   function call on macOS). The loop now keeps `self` and the frame in
   registers; its stack frame went from ~2.4 KiB to 784 bytes. `fib(30)` is
   at 0.18 s (CRuby 2.6: 0.14 s), the `while` loop at 0.48 s (CRuby: 0.69 s).
   Then `Value` was NaN-boxed into 8 bytes (16 before), with 48-bit inline
   Integers and larger ones boxed in the heap: memory for a value-heavy
   script 82 → 60 MB, speed about neutral (the dispatch loop, not value
   size, is the limit), immediates compared by bits (Hash lookups 2×).
   Hashes with more than 8 pairs got an index (open addressing over the
   insertion-ordered pairs, like mruby's split between small and big
   hashes): 250k inserts and lookups ~50 s → 0.12 s. Deletes leave dead
   entries that are compacted later (O(1) instead of shifting), and keys
   whose class defines `hash`/`eql?` are hashed and compared through them,
   raising if a callback changes the hash under the lookup.
   A third round worked on the instructions themselves: a peephole pass
   (jumps to returns), `x ± int` on a local in one instruction, a fused
   compare-and-branch for conditions on locals, `SendSelf`, a direct `Yield`,
   and no env for blocks that don't reach outer locals: fib(34) 1.32 → 1.06 s
   (CRuby 2.6: 0.71), a `while` loop 0.47 → 0.37 s (CRuby: 0.67), `times`
   0.15 → 0.12 s (CRuby: 0.11).
   Next: fewer frame copies per call, no heap object per block literal.
7. **Numbers.** Bignum (`num-bigint`, matching `mruby-bigint`), Rational, Complex.
8. **Enumerators.** `Enumerator`, external iteration (needs Fibers), `lazy`.
9. **Standard gems** as Cargo features: `mruby-io`/`mruby-dir`, `mruby-time`,
   `mruby-pack`, `mruby-random`, `mruby-struct`, `mruby-set`, `mruby-regexp`
   (map to the `regex` crate, or port mruby's own engine for compatibility),
   `mruby-sprintf` (largely done), `mruby-errno`, `mruby-socket`.
10. **Bytecode compatibility.** Encode `Op` into mruby's byte format and implement
    `.mrb` dump/load (`dump.c`/`load.c`), then ship an `mrbc`-compatible binary.
11. **Embedding API.** A safe Rust API in the spirit of `mruby.h`:
    `vm.define_class`, `define_method` with closures, typed argument extraction,
    `Value::Data` for wrapping Rust structs, `vm.funcall`. Optionally add a
    C ABI (`extern "C"` mirroring `mrb_*`) so existing mruby C gems can link.
12. **no_std/embedded.** mruby targets microcontrollers. Make `core` `no_std` + `alloc`
    and put stdio behind features.

## 5. Prior art worth reading

* **Artichoke** (github.com/artichoke/artichoke): a Ruby in Rust that *wraps* mruby
  through FFI and is gradually replacing pieces with Rust. It's a reference for the
  embedding API and core-library behaviour.
* **ruruby** by sisshiki1969 (github.com/sisshiki1969/ruruby) and its successor
  **monoruby**: a pure-Rust Ruby with its own parser, GC and JIT. Note that the
  crate name `ruruby` is taken on crates.io, so rename before publishing.
* **ruby-prism** crate: Prism's official Rust bindings.
* mruby's own docs: `mruby/doc/internal/{architecture,vm,opcode,gc,compiler,boxing}.md`.

## 6. Running mruby's test suite (`mrbtest`)

```sh
cargo run --release --bin mrbtest                    # all of mruby/test/t/*.rb
cargo run --release --bin mrbtest -- -v array.rb     # one file, every failure printed
cargo run --release --bin mrbtest -- --top 40        # longer "most common errors" lists
```

How it works:

* `tests/mruby/assert.rb` is a harness with the same API as mruby's `test/assert.rb`
  (`assert`, `assert_equal`, `assert_raise`, `assert_float`, …). It's written in the
  Ruby subset ruruby supports, so the numbers measure the test files and not the
  harness. Switch to mruby's own `assert.rb` once ruruby can load it (it needs
  splats, `&block`, `alias` and `class << obj`).
* `src/bin/mrbtest.rs` runs each file in a child process with a 20 s timeout, so
  crashes and endless loops stay contained. A file that doesn't parse as a whole is
  split into top-level chunks and the chunks that do parse still run.
* The columns are:
  * **OK / KO / Crash / Skip / Warn**: per assertion, as in mruby. Crash means an
    exception was raised inside `assert`, and Warn means the block made no assertions.
  * **Syntax**: assertions inside chunks ruruby can't parse.
  * **TopErr**: top-level code that raised outside any `assert`.
  * **pass%**: OK divided by the number of `assert` calls in the file.
* At the end it lists the most common syntax errors, exceptions and top-level
  errors. That list is the to-do list for the next steps.
* `cargo test` includes `tests/mrbtest_harness.rs`, which keeps the harness working.

Results (full reports in `docs/mrbtest-baseline.txt` and `docs/mrbtest-latest.txt`):

| | asserts | OK | KO | Crash | Syntax | TopErr | pass |
|---|---|---|---|---|---|---|---|
| step 1 baseline | 923 | 247 | 48 | 260 | 309 | 82 | 26.8% |
| after step 2 (parser) | 970 | 593 | 145 | 186 | 1 | 3 | **61.1%** |

The total grew because asserts inside loops are now counted as they run. Since
step 2, `mrbtest` always runs a file chunk by chunk (one top-level statement or
`assert` at a time), so a single top-level error doesn't hide the rest of the
file, and `__FILE__`/`__LINE__`/error lines refer to the real file.

What blocks the most assertions now (no longer syntax):

* **Subclasses of built-ins:** `class HashEntries < Array` with `HashEntries[...]`
  (32 in `hash.rb`). ruruby's Array/Hash/String values can't carry a subclass.
* **Visibility:** `private`/`protected` aren't enforced (many KOs in `syntax.rb`,
  `module.rb`, `kernel.rb`).
* **Missing core methods:** bang string methods (`upcase!`, `chomp!`, …),
  `String#[]=`, `rindex`, `byteslice`, `Range.new`, `NameError#name`, frozen objects.
* **mruby-specific test hooks:** `GC.stress`, `ar_entries`, `env_capture`,
  `MRUBY_PLATFORM`. mrbtest provides these from C, so ruruby's harness should
  provide equivalents (or skip them).

Writing the suite found one interpreter bug, now fixed: arrays and hashes that
contain themselves overflowed the native stack in `==`, `inspect`, `join` and
`flatten`. They now behave as in Ruby (`[1, [...]]`, `ArgumentError`, and
recursive pairs compare as equal).
